# Student Interview

This table describes the underlying information needed, asked as separate questions in **detailed mode**. In **light mode** (see SKILL.md Step 1), the same fields are gathered through four bundled open-ended prompts instead — the "why it matters" reasoning below still applies either way.

## Questions and why they matter

| Ask | Why it matters |
|---|---|
| **Student name** (asked first) | Makes the plan feel written for them, not a generic template. Use it in example sentences and the plan header. Always free text — never present suggested names as multiple-choice options; the tutor must type the real name. |
| **Pronouns** (asked second) | He/him, she/her, or they/them. Never infer from the name — a name doesn't reliably indicate pronouns. Use consistently throughout the plan and example sentences. |
| **Current level** | If the tutor doesn't know the CEFR level, ask what the student can already do in English (e.g. "can they hold a conversation about daily routine? write an email?") and infer a level from `cefr-levels.md` rather than asking the tutor to self-rate against CEFR labels they may not know. |
| **Location/hometown or country** | Ask for the actual place (city and/or country — "Barcelona," "Naples," "Osaka"), not a language-family checkbox. Two students from the same broad language family still deserve distinct, place-specific content, not interchangeable regional stand-ins. This does double duty: (1) real personalization material — weave in local references, regional context, culturally relevant topics, the way interests are used; (2) silently infer the native language and likely L1-interference errors from the location (see cheat sheet below) without needing to explain the linguistics back to the tutor. |
| **Interests, profession, hobbies** | The single highest-leverage personalization lever. A lesson on conditionals using a doctor's clinical scenarios, or a footballer's match commentary, sticks far better than generic "if I win the lottery" examples. |
| **Goal for learning English** | Determines topic register and skill priority: exam prep (IELTS/TOEFL/Cambridge) needs exam-format practice; work needs professional register and email/meeting language; immigration/relocation needs practical daily-life scenarios; general fluency has the most freedom. |
| **Session length** | Its own question, kept separate from activity choice — these are independent decisions, not one combined preference. Offer concrete choices: 30 minutes, 60 minutes, or "something else" (tutor specifies). Ask frequency separately if it's relevant to path planning. |
| **Activity choice** | Its own question: random from the teacher's list, a specific named activity, or the assistant's judgment. Needed even for path design since it determines the path table's Activity Type column. |
| **Specific request or "you choose"** | If the tutor has a required syllabus point (e.g. a coursebook unit, an exam skill), the plan must hit it. If open, use the goal + interests to choose something useful and motivating. |

Ask these as one batched round of questions where possible, but keep each distinct piece of information (name, level, session length, activity choice, etc.) as its own question rather than folding several into one — a tutor should be able to answer session length without also being forced to answer another preference in the same breath.

**Vocab constraint and vocab count, and home assignment, are NOT part of this initial round.** They only apply to an individual lesson's content, not to path design, so they're asked later, right before a specific lesson is actually drafted (see SKILL.md Step 4). Don't ask a tutor who just wants a learning path to also decide vocab style for a lesson that doesn't exist yet.

## L1 interference cheat sheet

Common error patterns by native language — use to anticipate errors and build a quick pre-emptive correction or extra drill into the lesson, not to stereotype every learner (individual variation is real; treat this as a starting hypothesis). Since the interview asks for a location rather than a language name, map the location to its likely native language yourself (Barcelona → Spanish/Catalan, Naples → Italian, Osaka → Japanese, etc.) before consulting this table — and apply it silently; the tutor asked about a place, not a linguistics lesson.

- **Spanish/Italian/Portuguese (Romance)**: false cognates (embarrassed/embarazada), gender agreement carried into English adjectives, "have" vs "be" for age/states ("I have 20 years"), present tense for future plans
- **Mandarin/Cantonese**: no articles (a/the) in L1 → article omission or overuse, no verb tense marking → tense errors especially with perfect aspect, topic-comment structure → unusual word order in complex sentences
- **Japanese/Korean**: subject/object particles instead of word order → word order errors, no articles, difficulty with plural marking (no obligatory plural in L1), politeness/register mapped onto English formality choices
- **Arabic**: no present tense "to be" (verbless sentences in L1) → omission of "is/are", different consonant-vowel patterns → specific pronunciation targets (p/b, no short vowel distinctions)
- **Russian/Polish/other Slavic**: no articles → article errors, no continuous aspect in the same way → overuse of simple tenses, complex case system doesn't map to English prepositions → preposition errors
- **Vietnamese/Thai**: no verb conjugation or tense marking in L1 → tense/3rd-person -s omission, tone-based L1 → stress and intonation challenges in English
- **German/Dutch**: fairly close to English structurally → fewer structural errors, but word-order differences with subordinate clauses and false cognates still appear

When the tutor names a language not listed here, reason from typological features (does the L1 mark tense/articles/plurals? what's its base word order?) rather than skipping the analysis.
